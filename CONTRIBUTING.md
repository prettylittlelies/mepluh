# Contributing to Mepluh

Mepluh is a community project and welcomes any kind of contribution from anyone!

## AI Policy

<!-- Adapted from Vencord, which adapted it from Ghostty. Credits to Mitchell Hashimoto -->

Mepluh has strict rules for AI usage:

- **AI slop will result in a block**. If code or text you submit is clearly generated by AI without human review and cleanup, you will be blocked from contributing to the project. Examples of slop include overly verbose text, unnecessary comments, overcomplicated code, failure to follow project conventions, and other signs of minimal human involvement.

- **All AI usage in any form must be disclosed.** You must state the tool you used (e.g. Claude Code, Codex) along with the extent that the work was AI-assisted.

- **The human-in-the-loop must fully understand all code.** If you can't explain what your changes do and how they interact with the greater system without the aid of AI tools, do not contribute to this project.

- **Don't post AI generated texts in issues, discussions or PRs**. AI is very good at being overly verbose and including noise that distracts from the main point. You can use AI to assist you, but you must trim it down and ensure it is concise and relevant.

## How to contribute

Contributions can be sent via pull requests to the `main` branch. If you're new to Git, check [this guide](https://opensource.com/article/19/7/create-pull-request-github).

Before working on a major change, open an issue describing it first so we can discuss before you invest time. This saves you a lot of time in case your feature is considered too niche or rejected for any other reason.

### Development setup

Mepluh uses [Bun](https://bun.sh) for everything. Node and npm are not required.

```sh
bun install
bun run typecheck
bun run inject
```

`bun run inject` builds Mepluh, closes Medal and injects it. Set `MEPLUH_REMOTE_DEBUGGING_PORT=9333` before launching Medal to attach Chrome DevTools to the renderer from outside.

Every pull request must pass `bun run typecheck` and `bun run build`.

### Code style

- Strict TypeScript. No `any`, no `@ts-ignore`, no non-null assertions to silence the compiler.
- No comments. Code should explain itself through naming and structure.
- Small, focused modules. Prefer a new file over a long one.
- Match the surrounding code: naming, idioms and file layout.
- UI is built with Medal's own components from `src/renderer/medal`. Only use Tailwind classes that already exist in Medal's stylesheet, since Medal ships a purged build.

## Write a plugin

Writing a plugin is the primary way to contribute.

Before starting your plugin:
- Consider if this plugin would be useful to a large portion of the userbase. We do not accept niche plugins
- Check existing pull requests to see if someone is already working on a similar plugin
- Familiarise yourself with our plugin rules below to ensure your plugin is not rejected

### Plugin structure

A plugin lives in `src/plugins/<name>/`:

- `index.ts` defines the plugin with `definePlugin`: name, description, category, options, patches, styles and the renderer `start` / `stop` hooks. It is bundled into both the main process and the renderer, so it must not touch the DOM at import time.
- `native.ts` (optional) defines main-process behaviour with `defineNative`: request blocklists, IPC handlers callable from the renderer, and a `start` hook.

Register the plugin in `src/plugins/index.ts`, and its native part in `src/plugins/natives.ts`.

### Patches

Medal's renderer is a set of Vite chunks. Patches rewrite chunk source as Medal loads it:

- `find` selects a chunk. Prefer `chunkMarker("renderer-SomeChunk")` from `@shared/chunkPatches`, which matches the chunk's own source map comment.
- `match` / `replace` rewrite it. Use `\i` in a regex to match any minified identifier, and `$self` in a replacement to reference your plugin's definition.
- Never rely on minified identifiers or export letters directly. They change on every Medal update.

After changing a patch, check **Mepluh → Patch Report** in Medal's settings to confirm it applied.

### Plugin Rules

- No raw DOM manipulation when a patch or Medal's React components can do the job
- No plugins that simply hide or restyle UI elements. This can be done with CSS or a theme
- No plugins that bypass Medal Premium or other paid features
- No plugins that automate actions against Medal's servers (auto-liking, follow bots, view inflation, API spam)
- No untrusted third party APIs. Popular services like GitHub are fine, but absolutely no self hosted ones
- No plugins that require the user to enter their own API key
- Do not introduce new dependencies unless absolutely necessary and warranted

## Write a theme

Themes are plain `.css` files with a header:

```css
/**
 * @name My Theme
 * @description What it does
 * @author you
 * @version 1.0.0
 */
```

Medal is styled with Tailwind v4 tokens, so most themes only need to override variables on `:root`, such as `--color-first-layer`, `--color-second-layer`, `--color-third-layer`, `--color-neutral-*`, `--color-foreground-*` and `--color-brand-primary-*`.

Built-in themes live in `src/themes`. Prefer generating them from a palette, like the Catppuccin themes do, over hand-copying values.

## Improve Mepluh itself

If you have any ideas on how to improve Mepluh itself, or want to propose a new plugin API, feel free to open an issue so we can discuss.

Or if you notice any bugs or typos, feel free to fix them!

## Help out other users

Answering questions and triaging bug reports in the issue tracker is always appreciated. The more, the merrier.
